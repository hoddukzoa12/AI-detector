# 1. 공개 웹사이트 불법광고 점검

공공 웹사이트의 공개 페이지에 은닉 광고가 남아 있으면 관리자는 일반 화면만 보고 문제를 놓칠 수 있다. 글자가 비슷한 다른 문자로 치환되거나 한글 자모가 분리되면 단순 검색이 어렵다. 투명 스타일이나 화면 밖 배치는 사람이 읽는 화면과 실제 DOM의 차이를 만든다.

이 도구는 관리자가 입력한 공개 URL을 시작점으로 페이지와 포함 iframe을 읽고, 은닉 기법이 확인된 광고 후보의 원문과 위치를 보존한다. 결과는 담당자가 다시 확인할 수 있는 JSON·상세 판정·근거 파일로 제공한다. 자동 삭제나 신고를 수행하지 않으며 판정 자체를 법적 위반 확정으로 제시하지 않는다.

대상 사용자는 공개 웹사이트 운영·점검 담당자다. 개발 실행은 npm과 Docker로 제공하고, 최종 사용자에게는 Node나 GPU 설치가 필요 없는 Windows 폴더형 앱을 준비했다. 기존 Infocutter 저장소의 소비자 기능과 새 점검 앱은 실행 경로가 분리되어 있다.

핵심 산출물은 네 DOM 기법과 일반·숨김 이미지 광고의 분리 결과, 필수 CLEF 분류, 선택 Gemini OCR, 원문·이미지 근거, Docker와 Windows ZIP이다. Linux 실행·정적 패키지·소형 실모델을 검증했다. 실제 Windows·대표 사이트 정확도·전체 배포 권리는 남은 조건이다.

# 2. 점검 흐름과 공개 범위

사용자는 공개 URL을 입력하고 후보 글자·소유 링크의 필수 CLEF 전송에 동의한다. 키·동의 없이는 시작할 수 없다. 이미지 OCR은 기본 꺼짐이며 켜면 정적 PNG가 Gemini로 전송된다. 실행 중 페이지 수와 확정·검토 건수, 현재 URL을 확인하고 필요하면 중단할 수 있다.

탐색 경계는 입력 URL과 같은 hostname이다. 쿼리가 다른 페이지는 구별하고 외부 사이트 링크·다른 서브도메인으로 큐를 확장하지 않는다. 포함된 외부 iframe은 해당 페이지의 구성 요소로 읽되 그 프레임 안의 링크를 외부 탐색의 시작점으로 삼지 않는다. 로그인·폼 제출·작성·수정·삭제는 제외한다.

새 브라우저 컨텍스트에서 공개 페이지를 읽으며 기존 확장의 광고 차단·마스킹을 먼저 적용하지 않는다. 긴 페이지의 끝에 있는 내용도 관측하고, 동적 DOM과 같은 src의 여러 iframe·중첩 iframe을 구별한다. 접근 실패나 상한에 도달한 페이지는 오류·미점검 URL로 남긴다.

화면의 확정 행을 열면 원문·유형·위치와 판정 상세를 확인할 수 있다. 수집 HTML을 화면에서 실행하지 않고 텍스트로 표시한다. 화면·다운로드·저장 결과가 같은 확정 자료를 가리키며, 결과 0건과 부분 완료·실패를 구분한다.

# 3. 네 은닉 기법과 오탐 구분

HOMOGLYPH는 원문에 비슷하게 보이는 다른 문자가 섞인 경우를 분석용 정규화와 비교한다. JAMO는 분리·조합된 자모를 복원해 광고 문맥을 확인한다. 복원문을 검색과 판정에 사용하더라도 공식 근거는 캡처한 원문을 유지한다.

TRANSPARENT는 요소와 조상의 투명도·색·스타일을 함께 관측한다. OFFSCREEN은 CSS 배치와 문서·viewport 좌표를 구분한다. 단순히 스크롤 아래에 있다는 이유로 화면 밖 은닉으로 판단하지 않는다. 접근성용 텍스트나 설명용 숫자·자모도 정상 반례로 취급한다.

광고 문맥은 CLEF만 판정한다. 은닉 형태나 광고 키워드만으로 확정·제외하지 않고 로컬 광고 판정·실패 fallback을 제공하지 않는다. 직접 원문과 가장 가까운 소유 anchor만 사용하며 부모 메뉴 글자·형제 광고 링크를 제목에 합치지 않는다.

탐지 단위는 원문을 소유한 최소 요소와 기법이다. 같은 요소에 여러 문자열이 있어도 같은 기법은 한 건이며, 한 요소가 서로 다른 두 기법에 해당하면 두 건을 출력한다. 동일 페이지·프레임·요소의 정체성을 유지해 중복 탐색으로 결과가 불어나지 않도록 한다. 합성 정답은 이 단위를 탐지 코드와 독립적으로 지정했다.

# 4. Gemini 추출과 CLEF 분류

OCR은 OpenRouter google/gemini-3.8-flash가 img·CSS 배경·before/after PNG 첫 프레임의 글자·읽기 상태를 추출한다. readable 원문만 CLEF로 보낸다. 부분 읽기·읽기 불가·무문자·오류·미선택을 구별하고 그림만 있는 광고·영상·캔버스·나머지 프레임의 탐지를 주장하지 않는다.

필수 cloudflare/clef의 고정 Decisions 응답에서 최고 확률 선택이 illegal_ad이고 0.8 이상이면 확정한다. 은닉 기법·위치는 로컬 DOM 관측이다. confidence와 확률은 별개이며 불확실·낮은 확률·오류는 검토로 남긴다. 일반 이미지와 은닉 DOM 결과를 구별한다.

CLEF에는 후보의 원문·정규화 텍스트·소유 링크를 전송하고 쿠키·전체 페이지·방문 기록은 보내지 않는다. 토크나이저는 고정 revision을 포함해 요청 상태의 토큰 수를 측정한다. 긴 후보를 나눌 때 UTF-16 원문 범위와 조각 상태를 남겨 일부만 분석한 사실을 숨기지 않는다.

양성 조각이 확인된 뒤 다른 조각이 실패하거나 중단되면 확인된 결과와 미완료 검토를 함께 보존한다. 중단 뒤 늦게 도착한 응답으로 확정 건수를 늘리지 않는다. 모델 가중치·Python·GPU는 배포하지 않고 키는 Node만 읽는다. 대표 한국어 인식·분류 성능은 별도 라벨로 측정해야 한다.

# 5. 근거·위치·공식 출력

공식 result.json에는 meta와 findings만 둔다. meta는 주제·진입 URL·시작/종료 시각·경과 시간을 담고, 각 finding에는 고유 ID·방문한 top-page URL·is_violation true·전체 위치·원문 evidence_text·하나의 technique 코드를 넣는다. 내부 오류나 검토 후보를 공식 결과 배열에 섞지 않는다.

iframe의 결과 URL은 프레임 URL로 바꾸지 않는다. top-page URL을 유지하며 location에 iframe 소유자들의 전체 경로와 최종 요소 선택자를 기록한다. 같은 src를 쓰는 프레임도 위치가 다르고 중첩 프레임 경로는 한 번만 포함된다.

result_extra.json은 같은 실행 meta의 ETC·IMAGE_AD_OCR 이미지 결과다. V2 review·finding-details·scan-status·ocr JSON은 검토·CLEF 조각·추출 원문/범위·원본/PNG 해시·소유 위치·미완료를 연결한다. 두 결과와 이미지를 서로 다른 ID로 구별하며 인증된 PNG만 미리보기한다.

runs/<runId>에 실행별 자료를 보존하고 최신 파일은 원자적으로 교체한다. SHA256는 실제 저장한 바이트에서 계산한다. 저장 오류가 나도 이전에 확인된 실행을 지우거나 실패를 광고 없음으로 바꾸지 않는다. 최신 표시 파일과 실행 ID를 함께 확인해 이전 결과를 새 결과로 오인하지 않도록 한다.

# 6. 실행 환경과 키 관리

npm 실행은 Node 24 LTS와 Playwright Chromium을 사용하며 기본 결과 폴더는 앱 작업 폴더의 output이다. Docker는 브라우저·시스템 라이브러리를 포함한 고정 이미지로 실행하며 컨테이너 /app/output을 호스트 output에 연결한다. 컨테이너 UID/GID 1001에 쓰기 권한을 제공한다.

Windows 배포는 Electron 폴더와 ZIP이다. Chromium·production 의존성·자체 점검용 Node·토크나이저·고지를 함께 포함한다. 사용자는 Node·Docker·Python·GPU·AI 모델을 설치하지 않는 구성을 목표로 한다. 앱은 GPU 가속을 끄고 루프백의 로컬 화면을 연다. 실제 대상 Windows PC의 동작은 아직 확인해야 한다.

Windows의 기본 출력과 .env 위치는 실제 Inspektor.exe 폴더다. npm은 작업 폴더의 .env, Docker Compose는 호스트 .env를 사용한다. OS 환경변수가 파일보다 우선한다. 키를 교체하면 앱을 완전히 종료하고 다시 실행하며 재빌드는 필요 없다. 화면에는 키가 설정되었는지만 전달한다.

자체 점검은 모의 OCR/CLEF로 DOM25건·빈 결과0건·이미지·메뉴 네 실행을 검사하며 외부 요청을 하지 않는다. 결과는 지정 출력 루트의 self-test 아래에 새로 보존해 일반 실행 결과를 덮어쓰지 않는다. Windows에서는 앱을 종료한 뒤 Inspektor.exe --self-test를 실행하고 실제 종료 코드와 보고서를 확인한다.

# 7. 수행한 검증과 차별점

Linux npm의 단위 471개·통합 14개와 typecheck·lint·build·자체 점검이 통과했다. 독립 합성 사이트는 네 유형과 복수 기법, 내부 링크·쿼리·긴 페이지·같은 src/중첩/외부 iframe을 제공하며 원문·기법·위치를 정확히 비교한다. 양성 25건 실행은 의도적 접근 실패를 포함한 partial이며 정상 반례는 completed 0건이다.

생산 서버/UI에서 두 결과·PNG·여섯 다운로드·중단·해시를 확인했다. 모의 이미지 39발생·20양성 소유자와 메뉴 22음성/주변 5양성으로 원문·링크 귀속을 검사했다. 별도 실제 OCR 8·CLEF 10요청은 모두 HTTP200·재시도 0이었다. 읽을 수 있는 6이미지 정답 162 code point와 문자 차이 0, 무문자/읽기 불가 상태도 일치했다. CLEF 10건 중 9개가 수동 선택과 일치했고 MEMBER는 uncertain 검토였다. OCR 지연 2,492~6,496ms·CLEF 275~913ms, 제공 비용 합계 0.01596897달러다. 이 표본을 전체 정확도로 주장하지 않는다.

Docker에서도 실제 서버·화면 25행과 호스트 볼륨의 해시를 확인했다. Windows 689파일·25 x64 PE·ZIP·고지·전체 바이트를 정적으로 검증했다. 공식 metadata503으로 기존 검증된 동일 버전 캐시를 재사용한 사실을 기록한다. PE 구조가 올바르다는 사실을 Windows 실행 성공으로 바꾸지 않는다.

차별점은 광고를 단순 문자열 목록으로 보여 주는 대신 DOM 은닉 기법과 광고 문맥을 결합하고, 프레임 전체 위치·원문·부분 실패·검토 상태를 함께 보존하는 데 있다. 결과가 적은 실행도 검사하지 못한 범위를 표시해 운영자가 실제 확인 범위를 판단할 수 있게 한다.

# 8. 적용 계획과 남은 조건

첫 적용 전 GPU 없는 Windows 11에서 ZIP 해제·exe 실행·시작/중단·원문과 iframe·JSON과 근거·정상 종료·자체 점검을 확인한다. 운영망 접근과 30분 평가 조건도 대상 PC에서 측정한다. 현재 Windows 테스트 환경이 없어 이 단계는 보류이며 제출 준비 완료로 표시하지 않는다.

운영 대상의 한국어 배너·광고·기사·안내를 독립 라벨링해 OCR/CLEF 정확도·임계값·운영망·두 실키 교체를 평가해야 한다. 이전 toonkor22메뉴 오탐의 귀속 원인은 수정했지만 현재 코드의 사이트 재평가는 미수행이다. 소형 표본과 모의 회귀를 실사이트 정확도로 해석하지 않는다.

원본 저장소에는 루트 LICENSE가 없고 Flutter 하위 앱의 Apache 라이선스가 존재한다. 전체 소스 재배포 전 권리 범위를 확인해야 한다. 의존성·Chromium·Node·Electron·토크나이저의 고지는 보존하고 확인되지 않은 루트 라이선스나 원저작권자 허가를 새로 작성하지 않는다.

신청자 인적 사항·제출 이메일·공식 신청서 작성은 사용자가 확인한다. 자동 업로드·이메일 발송·사이트 수정은 이 앱의 범위에 포함하지 않는다. 남은 실제 환경·성능·권리 조건이 해결되면 관리자의 수동 검토 절차와 보관 정책을 정해 점검 결과를 운영 업무에 적용한다.
