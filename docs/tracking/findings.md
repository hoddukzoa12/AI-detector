# 미해결 사항

## 실제 사이트 OCR·분류 성능 미측정

- 조건·증상: 이전 toonkor 로컬 실행의 확정22건은 모두 MEMBER·MENU 제목 오탐이었다. 새 코드는 형제 광고 링크 상속과 로컬 광고 판정을 제거하고 실제 Chromium에서22메뉴 음성·5광고 양성의 귀속 회귀를 통과했다. 하지만 현재 코드의 같은 사이트 유료 재점검과 대표 라벨 평가는 수행하지 않았다.
- 영향: 원인 수정·합성 입력 회귀를 실사이트 오탐 감소·전체 광고 탐지율로 주장할 수 없다. 글자 없는 그림·복잡한 배너·다른 애니메이션 프레임도 누락될 수 있다.
- 이번에 남겨 둔 이유: 실제 평가는 승인된 소형 합성 OCR 8·CLEF 10요청으로 제한했다. 읽을 수 있는 6이미지 문자 차이 0·읽기 상태8/8·CLEF수동 선택9/10은 쉬운 표본이며 MEMBER는 non_ad 대신 uncertain 검토였다. 대표성 있는 사이트 라벨과 실제 두 키 교체 검사는 없다.
- 대응: 독립 라벨·별도 요청 상한·운영망으로 추가 평가하고 이전 사이트 원문/결과를 보존한다. 불확실 검토를 확정 오탐이나 광고 없음으로 바꾸지 않는다.

## 실제 Windows 11·평가 시간 미검증

- 조건·증상: Linux에서 새 Windows ZIP의689파일·PE·CRC/실바이트를 정적으로 검증했으나 GPU 없는 Windows 11 GUI와30분 평가 기록은 없다.
- 영향: 플랫폼의 Chromium·파일 권한·중단·종료·키 변경·자체 점검 문제를 배포 전에 확인하지 못했다.
- 이번에 남겨 둔 이유: 사용자가 현재 Windows 테스트 환경이 없다고 확인했으며 개발 환경은 Linux다.
- 대응: 대상 PC에서 ZIP 해제·exe UI·두 결과·PNG/OCR 근거·키 변경·자체 점검·중단/종료·시간 상한을 확인한다. 기존 Flutter Windows 빌드는 새 앱 검증과 별개다.

## 초기 스크립트에 인증 주소 예외가 없음

- 조건·증상: WebView는 `buildInfocutterUserScripts()`를 URL 조건 없이 `initialUserScripts`에 등록하고 빌더도 URL을 받지 않는다.
- 영향: 후속 런타임·요청 예외만으로 초기 주입이 차단된다고 보장할 수 없다. 공모전의 로그인 진입 금지 정책을 이 경로에 맡길 수 없다.
- 지금 해결하지 않은 이유: 기존 Flutter 소비자 코드 수정은 이번 범위 밖이며 실제 기기 재현은 하지 않았다. 새 수집기는 이 주입 경로를 사용하지 않는다.
- 대응: 기존 Flutter를 다시 사용할 때 초기 주입까지 인증 배제를 검증한다.

## AI 후보 수집이 필수 유형을 누락할 수 있음

- 조건·증상: Flutter 수집기는 숨김·작은 요소를 제외하고 본문 대신 길이·메타데이터만 보내며, Chrome은 일부 태그·120개·200자로 제한한다.
- 영향: 투명·화면 밖 은닉과 긴 페이지 광고가 분석 입력에서 빠진다.
- 지금 해결하지 않은 이유: 기존 소비자 수집기를 수정하는 일은 이번 범위 밖이다. 새 앱의 별도 원문·스타일 수집은 실제 브라우저에서 검증했다.
- 대응: 기존 소비자 AI 기능을 바꿀 때 숨김·긴 텍스트 수집 범위를 다시 확인한다.

## 라이선스 표기 불일치

- 조건·증상: 원본 README는 MIT와 루트 LICENSE를 가리켰으나 근거 없는 표기는 제거했다. 루트 LICENSE는 여전히 없고 `apps/browser/LICENSE`에는 Apache-2.0과 원본 저작권 고지가 있다.
- 영향: 공모전의 전체 소스 제출과 이후 배포에서 허가·고지 범위를 단정할 수 없다.
- 지금 해결하지 않은 이유: 원저작권 확인과 권리자의 루트 라이선스 결정이 이루어지지 않았다.
- 대응: 원본과 자체 작성 부분을 구분하고 권리자가 라이선스를 결정한 뒤 배포 고지를 작성한다.

## 기존 Chrome 설치·재주입·템플릿 서버

- 조건·증상: lock 파일은 공용 빌드 패키지의 옛 경로를 쓰고, service worker 재주입 목록에는 선택자 전역 패키지가 빠져 있다. 템플릿 서버는 없는 `scripts/lib.mjs`를 import한다.
- 영향: `npm ci`, 설치 전에 열린 탭의 선택 모드, 템플릿 서버 시작이 각각 실패할 수 있다. 재주입 문제는 이번 작업에서 브라우저로 재현하지 않았다.
- 지금 해결하지 않은 이유: 기존 소비자 Chrome 빌드·재주입·템플릿 서비스는 새 앱의 실행 의존성이 아니며 이번 변경 범위 밖이다.
- 대응: 사용하는 경로만 수정·검증하고 lock 갱신은 별도 변경으로 분리한다.

## 기존 저장소와 프레임 의미의 차이

- 조건·증상: Chrome과 Flutter의 프로필 적용·예외·이전 규칙 버전 처리·템플릿 id가 다르며 iframe 식별은 origin+pathname 위주다.
- 영향: 데이터 교환을 완전 호환으로 오인하거나 기존 위치를 평가용 위치로 쓰면 데이터 손실·오탐 위치가 생길 수 있다.
- 지금 해결하지 않은 이유: 기존 사용자 기능의 동등성 구현은 전환 목표가 아니고 새 앱은 별도 전체 프레임 위치를 구현·검증했다.
- 대응: 재사용하는 코덱은 기존 입력 보존을 검사하고 평가 위치는 별도 계약으로 구현한다.

## 기존 CI와 검증 범위

- 조건·증상: GitHub workflow가 앱 하위에 있어 저장소 루트에서 실행되지 않는다. Chrome content DOM·Flutter 실기기·Windows 실행에 이번 작업의 검증 결과가 없다.
- 영향: 단위 테스트나 코드 존재를 제출 앱의 동작 검증으로 잘못 보고할 수 있다.
- 지금 해결하지 않은 이유: 기존 제품 CI 이동은 이번 범위 밖이고 실제 Windows 환경이 없다. 새 앱의 npm·Docker 실행 검사는 별도 수행했다.
- 대응: 기존 CI를 수정할 때 루트 workflow 경로를 확인하고 새 앱은 실제 Windows 환경에서 추가 검증한다.

## 기존 개발 서비스의 접근 제어

- 조건·증상: Chrome AI 키는 암호화되지 않은 `chrome.storage.local` 설정 객체에 보관된다. 템플릿 서버는 토큰 미설정 시 요청을 허용하고 CORS 기본값은 `*`지만 누락된 import로 시작이 막혀 있다. 디버그 브리지의 `page.getText`, `page.click`, `page.fill`은 민감 동작 목록에 없어 토큰 없이 현재 페이지를 읽거나 조작할 수 있는 코드 경로가 있다. 실기기 재현은 하지 않았다.
- 영향: 개발용 경로를 그대로 제출 서비스로 노출하면 승인된 점검 정책을 보장하지 못한다.
- 지금 해결하지 않은 이유: 기존 개발 서비스 수정은 이번 범위 밖이고 새 앱에서 연결하지 않는다.
- 대응: 개발 서비스를 루프백에 한정하고 릴리스의 필수 경로에서 분리한다. 검증되지 않은 접근 제어를 보장으로 표현하지 않는다.
