# 0005. 공공 웹사이트 점검 공모전 전용 도구로 전환

- 날짜: 2026-10-04
- 상태: 사용자 확인 완료, 새 앱 구현·Linux 검증

## 배경

기존 인포커터는 사용자가 방문한 페이지를 골라 가리는 제품이다. 공모전은 진입 URL 하나로 사이트 내부를 자동 탐색하고 숨겨진 불법광고의 위치·유형을 제출해야 한다. 기존 모바일·마스킹 제품과 공모전 도구를 함께 개발하면 우선순위와 검증 범위가 달라진다.

## 결정

사용자는 기존 제품에 점검 모드를 덧붙이는 선택 대신 공모전 전용 도구로 전환하기로 정했다. 현재 저장소의 구현은 재사용 기반으로 유지하고, 소비자 제품의 기능 확장을 목표로 삼지 않는다. 제출 환경은 GPU 없는 Windows 11이다. 사용자는 npm 기반 개발과 Windows 실행 파일 준비를 선택했다. 새 점검 화면과 TypeScript DOM 처리 재사용을 목표로 하고 Flutter 앱 전체 개조를 실행 기반으로 채택하지 않는다. 현재 Windows 테스트 환경이 없으므로 웹·Playwright·Electron 구성과 폴더형 ZIP을 구현했으며 실제 Windows 실행은 보류다.

## 대안

- 기존 제품 유지와 점검 모드 추가: 사용자는 별도 목표를 함께 운영하는 방향 대신 공모전 집중을 선택했다.
- 기존 제품 문서만 정리: 자동 점검 제출 목표를 준비하지 않으므로 선택하지 않았다.

- 기존 Flutter Windows 앱 개조: 화면·WebView·파일 저장을 재사용할 수 있지만 Windows 기반 검증이 필요하다. 사용자는 npm·Docker 개발과 Windows 패키징을 포함한 대안을 확인한 뒤 npm 기반 새 화면을 선택했다.

## 결과

소비자용 프로필 우선순위·자동 마스킹·모바일 동등성을 공모전의 업무 규칙으로 적용하지 않는다. DOM·선택자·근거 보존 코드를 재사용할 수 있지만 필수 네 유형·자동 순회·평가용 JSON은 별도 구현과 검증이 필요하다. 이번 결정은 기존 소스 삭제나 원격 저장소 변경을 승인한 것이 아니다.
