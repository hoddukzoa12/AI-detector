# 구현 시 주의점

## 숨겨진 광고가 후보에서 사라짐

Flutter AI 수집기는 가로 80px·세로 40px 이상이고 display·visibility·opacity 조건을 통과한 요소만 후보로 고른다. 텍스트 본문 대신 길이와 요소 메타데이터를 AI에 전달한다. 투명·작은 광고를 찾는 수집기로 그대로 쓰면 필수 유형이 후보에 들어가지 않는다. 숨김 요소와 부모 스타일을 포함하는 별도 읽기 경로를 만들고, 보이는 광고·투명 광고·display none·작은 글자 사례에서 실제 수집 결과를 확인한다.

Chrome AI 수집기는 일부 컨테이너 태그와 이미지·영상만 고르고 최대 120개·각 텍스트 200자까지만 수집한다. 공모전 성능 검사를 이 한도 아래의 사례로만 통과시키면 깊은 페이지와 긴 게시글의 누락을 놓친다. 페이지 탐색 한도와 텍스트 분석 한도는 별도로 설계하고 원문 근거는 자르지 않은 값으로 보존한다.

## 탐색 전에 마스킹하면 은닉 기법이 바뀜

기존 렌더러는 `data-infocutter-*-hidden` 속성·스타일과 ContentBlocker를 사용해 숨긴다. 키워드 감시는 블러를 적용하고 지연 이미지 스크립트는 리소스 상태를 바꾼다. 이 상태를 조사하면 사이트 원래의 CSS와 도구가 만든 CSS를 혼동한다. 자동 수집에서 기존 차단 경로를 연결하지 않고, 변화 전후 DOM·스타일 사례로 수집 경로가 사이트를 변경하지 않는지 확인한다.

## 위치가 페이지 안에서 유일해도 프레임까지 유일하지 않음

기존 `frameScope`는 origin+pathname을 사용해 쿼리·중첩 부모 경로를 담지 않는다. 같은 src의 iframe 두 개와 서로 다른 쿼리 문서가 구분되지 않을 수 있다. 제출 위치는 상위 프레임부터의 경로와 내부 선택자를 함께 만들어 다시 조회한다. 같은 프레임 주소가 여러 번 나오거나 부모 프레임이 중첩된 사례를 별도로 확인한다.

## 로그인 페이지 배제가 초기 주입을 덮지 않음

후속 런타임 적용·요청 콜백에 인증 주소 예외가 있어도 `initialUserScripts`는 URL 조건 없이 등록된다. 콜백 예외만 보고 모든 주입이 차단되었다고 판단하면 안 된다. 점검용 세션의 로그인 진입 정책과 초기 스크립트 경로를 함께 확인한다. 현재는 코드 대조로 확인했으며 실제 기기 재현은 하지 않았다.

## 확장 빌드·재주입 목록이 다름

`public/manifest.json`의 스크립트 목록은 빌드가 덮어쓴다. `scripts/build.mjs`가 실제 목록을 만들고 service worker는 별도 목록으로 재주입한다. 현재 service worker 목록에는 선택자 규칙 전역 패키지가 빠져 있다. 빌드가 통과해도 설치 전에 열린 탭에서 전역 심볼이 없어 실패할 수 있다. 두 목록을 비교하고 변경 후 실제 기존 탭과 새 탭에서 확인한다.

IIFE 패키지의 새 export는 빌드의 반환 목록에도 추가해야 한다. 타입 선언에만 추가하면 타입 검사는 통과하고 content script에서는 undefined가 된다. shared와 content의 선택자 생성 구현도 별개이므로 테스트가 어느 함수를 검증하는지 확인한다.

## 의존성 설치·템플릿 서버 함정

기존 Chrome lock 파일은 공용 빌드 패키지의 옛 상대 경로를 가리킨다. 깨끗한 checkout에서 `npm ci` 실패가 과거 기록에 있으며 현재 경로 불일치도 남아 있다. 기존 검증을 위한 우회는 `npm install`이고 이 명령이 lock 파일을 바꿀 수 있으므로 기능 변경과 분리한다.

템플릿 서버 스크립트는 존재하지 않는 `scripts/lib.mjs`를 import한다. 옵션 화면이 있다는 이유만으로 서버가 실행된다고 기록하지 않는다. 공모전용 도구의 필수 서비스로 연결하지 않는다.

## 테스트 성공이 플랫폼 실행 성공은 아님

기존 Chrome 단위 테스트는 DOM 없는 Node 환경에서 실행된다. Flutter의 주입 JS 검사는 파싱·전역 노출·생성물 동기 등을 확인하지만 실제 WebView 탐지 기능을 검증하지 않는다. Windows 프로젝트가 있다는 사실과 Windows 빌드 성공도 다르다. 제출 PC에서 앱 실행·탐색·파일 출력을 별도로 확인한다.

기존 Flutter에는 프로젝트별 SDK 고정 파일이 없다. 다른 SDK의 포맷 결과를 기능 변경과 섞지 않는다. 코드에 고정된 WebView 의존성을 먼저 설치한 뒤 플랫폼 실행을 확인한다.

## 근거 파일의 의미

Chrome은 매칭 블록 outerHTML을 저장하고 Flutter는 페이지 HTML을 저장하는 등 기존 캡처 범위가 서로 다르다. 전체 DOM 보존이라는 README 문구를 재사용 근거로 삼지 않는다. 파일 해시와 캡처 범위를 함께 기록하고, 해시가 시각의 신뢰성이나 법적 효력을 증명한다고 주장하지 않는다.

## 전체 iframe 경로를 두 번 붙이면 선택자가 실패함

dom 관측의 element.location은 이미 top-page부터의 전체 프레임 경로다. detection에서 framePath를 다시 prefix하면 같은 iframe 소유자 경로가 반복되어 실제 DOM 조회가 실패한다. 실제 crawler 자료의 전체 위치를 그대로 전달하고 framePath는 정체성·근거로 별도 유지한다. 같은 src·중첩·외부 프레임 여섯 정답을 crawler→detector→실제 프레임 DOM에서 대조해 확인했다.

## 페이지 생성 중 취소가 stopping에 머무름

진행 결과가 17건인데 중단 후 Chromium이 사라져도 종료가 75~90초 이상 지연되었다. context.close가 끝나도 진행 중 context.newPage RPC가 정리되지 않았다. Browser.close를 즉시 한 번만 호출하고 동일 promise를 finally에서도 기다리면 생성 중 RPC가 종료되어 작업 묶음과 저장이 완료된다. 브라우저 launch 이전 중단에서는 없는 browser에 대한 완료 promise를 캐시하지 않는다. 실제 UI 취소·파일 해시 고정·SIGTERM 종료와 잔류 Chromium 부재를 확인했다.

## AI 양성 뒤 미완료를 없애면 근거가 손실됨

후보 전체의 마지막 응답만 기다리면 먼저 확인한 양성이 취소나 다음 요청 오류로 사라질 수 있다. 초기 조각 계획·진행·완료 응답을 복제해 전달하고 확인된 양성은 즉시 보존한다. 중단 뒤에는 새 진행을 수락하지 않고 pending/running을 미시작/취소로 정리한다. 양성과 미완료가 함께 있는 자료와 늦은 양성 응답으로 결과·archive가 바뀌지 않는지 검사했다.

## 저장 시간과 실제 바이트 해시

저장 시작 전에 종료 시각을 고정하면 근거 작성 시간을 빼먹는다. 원문·검토·상세를 staging에 작성한 뒤 종료 시각을 확정해 공식 결과·상태·manifest를 작성한다. latest 표시는 마지막에 쓰고 실패하면 검증된 archive와 실패 표시를 보존한다. 해시는 메모리 객체를 재직렬화한 값이 아니라 실제 저장 바이트로 비교한다.

## CLI import가 자체 점검을 두 번 실행함

bundle 안의 import.meta.url 기반 main 판정은 import한 실행 도구도 진입 파일처럼 인식할 수 있다. CLI와 독립 검증 함수를 같은 파일에 두지 않고 부작용 없는 verification.ts로 분리했다. Docker smoke가 helper를 import했을 때 CLI가 자동 실행되지 않음을 실제 저장 경로와 검사 결과로 확인한다.

## Docker vfs는 표시 캐시보다 공간을 많이 씀

vfs에서 이미지·빌드 단계·컨테이너 쓰기 layer가 실제 복사되어 docker buildx du의 표시 MB보다 overlay 사용량이 크게 증가했다. 병렬 Windows 패키징/빌드/실행 중 Chromium의 mkdtemp가 ENOSPC로 실패했다. 이 앱에서 만든 사용하지 않는 캐시 ID만 확인·제거하고 실행 검사를 순서대로 재수행해 통과했다. 외부 이미지·volume을 일괄 삭제하지 않는다. 느린 브라우저 시작은 이전 500ms deadline 검사에서 콜백 진입 전에 제한을 맞았다. 현재 대기 콜백 기한 검사는 launch spy와 소유한 Browser/Context double로 진입·TIME_LIMIT·미방문·새 page 금지·close 한 번을 검사하고 finally에서 spy를 복원한다. 실제 Chromium 취소 검사는 별도로 유지한다. Docker 자체 점검도 최초 1500ms 정답 페이지 접근 제한으로 8건만 확인된 실패가 있었으므로 탐지 누락과 접근 실패를 status에서 구별하고 실패·재검사 기록을 함께 보존한다.

## 컨테이너 자산과 근거의 권한이 다름

고정 Playwright 이미지의 pwuser는 UID/GID 1001이다. 빌드 사용자의 0600 파일을 그대로 복사하면 다른 UID에서 runtime 모듈을 읽지 못한다. 코드·production 의존성·토크나이저에는 읽기/탐색 권한을 주되 일반 결과는 비공개 권한을 유지한다. Docker 검증의 host-readable chmod는 새 합성 출력에만 적용한다.

## Windows Chromium 고지와 Node 버전 구분

matching Windows resources.pak의 DataPack v5 resource 38941은 6바이트 크기를 포함한 Brotli payload다. 고정 공식 ZIP에서 전체 credits HTML을 추출하고 pak·결과 해시를 기록해야 링크 목록만 제공하는 불완전 고지를 피한다. GUI 서버는 Electron 내장 Node, 자체 점검은 bundled node.exe에서 실행하므로 외부 Node 24.19.0을 GUI 내장 버전으로 기록하지 않는다. PE와 정적 고지 검사는 Windows 실행 증거가 아니다.

## running 알림과 실제 AI 요청은 시점이 다름

running 알림 안에서 동기 중단하면 HTTP 호출은 0건이어도 상태만 running이 될 수 있다. transport 호출 여부를 따로 확인해 이 조각과 뒤의 미요청 조각을 not_started로 끝낸다. 실제 transport 중 중단한 조각만 cancelled다. application은 같은 chunkId·원문 범위의 최종 미시작 표시만 받아 정리하고 이미 수락한 양성과 범위는 바꾸지 않는다. 알림 시점 중단·실제 요청 중 중단을 분리해 검사했다.

## 취소 후 화면이 최종 근거를 읽지 않음

취소 전에 시작한 조회를 차단하려고 artifacts를 계속 막으면 실행 상태만 cancelled가 되고 상세·검토에는 running이 남는다. 취소 때 조회 세대를 바꾸되 현재 세대의 terminal API 응답에서는 최종 artifacts를 다시 읽는다. 즉시 종료·stopping 뒤 종료·취소 요청 실패의 polling 복구와 이전 세대 응답 배제를 실제 Chromium에서 검사하고 생산 서버의 최종 청크와 화면을 정확히 비교했다.

## 관측 스타일과 저장 스타일의 위치 기준이 다름

수집 자료의 조상 style 선택자는 top-page 전체 경로여서 detector가 소유 요소와 비교할 수 있다. 그대로 근거 JSON에 저장하면 프레임 내부에서 조회하는 선택자가 다시 프레임을 가리켜 실패한다. application에서 저장할 때 해당 framePath의 정확한 접두사만 한 번 제거하고 관측 자료·finding 전체 경로는 유지한다. 중첩 srcdoc과 선택자 안의 quoted >>>를 실제 캡처·저장·프레임 DOM 조회로 검사했다.

## background-image 누락은 정상 글자를 투명으로 만듦

검출기는 배경 이미지가 있으면 같은 색 판정을 보류하지만 수집기가 background-image를 빼면 흰 글자·검은 그라데이션의 실제 가시성이 사라지고 기본 흰 배경과 같은 색으로 오인한다. 소유 요소와 조상의 계산 background-image를 함께 캡처한다. 실제 Chromium의 소유자·조상 그라데이션 정상 두 건을 제외하고 진짜 같은 색·opacity 0 두 건은 유지하는 반례를 확인했다.

## 같은 문구를 집계 중복으로 추측하면 숨긴 부모가 사라짐

투명 색이나 0px 부모가 직접 가진 광고 문구와 보이는 자식 문구가 같으면 후보가 0건이었다. 수집기는 이미 직접 TEXT_NODE 원문만 기록하는데 탐지기가 자식 원문을 부모에서 빼서 집계 중복을 추측했다. 이 추측을 제거하고 동일 소유 위치만 중복 제거한다. 실제 Chromium에서 투명·0px 부모의 원문 보존, 부모·자식·형제 각각 유지, 직접 원문 없는 집계 부모 미수집, 반복 수집 중복과 정상 가시 반례를 검사했다. DOM·스타일·원문 자료도 변경되지 않았다.

## 형제 광고 링크를 메뉴 원문에 합치면 정상 제목이 확정됨

수정 전 toonkor 로컬 실행의22확정은 MEMBER·MENU 각각11건이었다. 닫힌 사이드바 스타일 자체는 실제 관측이지만 부모 메뉴의 토토 링크·가입·문의 글자를 제목의 광고 문맥으로 상속했다. 관련 링크를 가장 가까운 소유 anchor로 제한하고 직접 TEXT_NODE 외 집계 문맥을 제거했다. 실제 Chromium의22음성·주변5양성 입력 회귀를 모의 CLEF로 확인했다. MEMBER/MENU 제외 목록을 만들지 않았으며 실제 모델의 사이트 정확도는 별도다.

## 같은 이미지 캐시와 같은 광고 소유자는 다른 단위

동일 PNG를 여러 요소·프레임에서 쓰면 추출 캐시는 전송 해시·규격의 완료 응답만 재사용한다. 원본/PNG 참조·imageId·소유 링크·분류는 각 발생/소유자에 남긴다. 여러 CSS 레이어를 한 소유자에 합칠 때 읽힌 글자만 정해진 순서로 연결하고 원래 UTF-16 범위를 보존한다. 읽기 불가·미처리 레이어를 지워 전부 검사했다고 표시하지 않는다.

## 차단된 읽기 요청은 치명 런타임 오류가 아님

로그인·외부 이동·비읽기 요청의 진단 message에 fatal이라는 문자열이 있어도 실행 실패로 추측하지 않는다. 수집기의 실제 치명 종료 flag를 구별하고 의도적 중단·자원 상한은 부분/중단으로 보존한다. 생산 Chromium 정책 반례와 치명 launch/저장 실패를 따로 검사했다.

## 저장 직전 검증과 최신 표시가 서로 다른 실패 경계

archive를 만든 뒤 최신 파일 교체 중 실패하거나 PNG가 바뀌면 메모리 DTO의 path/hash를 성공처럼 유지하지 않는다. 실제 등록 archive를 재검증하고 실패 overlay·saved flag를 정확히 반영하며 이전 최신 표시는 보존한다. 늦은 callback으로 이미 종료한 원문/참조를 바꾸지 않는다.

## signal로 끝난 자식은 exitCode가 null일 수 있음

이미 SIGTERM으로 끝난 자식은 exitCode null·signalCode SIGTERM이다. exitCode만 보고 다시 기다리면 Docker/자체 점검 정리가 멈춘다. 두 종료 값을 확인하고 제한된 SIGTERM 대기 뒤 SIGKILL을 적용한다. 이미 끝난 signal·숫자 종료·강제 종료를 독립 프로세스로 확인했다.

## 검증 병렬 실행은 브라우저 취소 지연을 바꿈

초기 통합 코드의463단위와 실제 브라우저 통합을 동시에 실행하면 자원 경합으로 기존 취소 검사가 시간 초과했다. 같은 코드·같은 기한을 순차 실행해463단위와14통합이 통과했다. Docker vfs·Windows ZIP도 순서대로 검사하며 전체 이미지/volume을 일괄 정리하지 않는다. 모의 요청 수는 실행 경로마다 다를 수 있으므로 실제 모델 호출 기록과 혼동하지 않는다.

## 공식 metadata HTTP503과 검증된 캐시의 증거를 분리

고정 Electron SHASUMS 재요청이503으로 두 번 실패했다. 이전에 성공한 동일 버전 Electron/Node checksum·Chromium LICENSE와 ZIP 해시를 독립 대조한 좁은 임시 재사용 경로로 패키지를 생성했고 전체689파일·ZIP·소스를 다시 비교했다. 제품 downloader의 고정 HTTPS/TLS는 바꾸지 않았다. 캐시 출처·해시·실패 기록을 남기며 새 HTTP 성공·서명 검증·재배포 권리 확인으로 발표하지 않는다.

## 최초 이미지 주소와 실제 확보 주소가 다름

리다이렉트 자산의 PNG와 해시는 맞지만 OCR 기록의 imageUrl은 최초 주소로 남았다. 페이지 관측에서 발생 기록을 먼저 복제한 뒤 원본 확보 callback의 최종 주소를 옮기지 않았기 때문이다. 같은 발생의 확보된 원본이 있을 때 최종 주소만 반영하며 DOM 원문의 src·발생 ID·위치·해시는 유지한다. 성공과 디코딩 실패의 저장본/조회 자료를 대조하고 미확보 실패·data/blob null·종료 후 callback 반례를 검사했다.

## fixed 이미지의 기준은 항상 viewport가 아님

오른쪽·아래 fixed와 완전 clip을 누락했고, 스크롤로 위·왼쪽에 놓인 정상 이미지가 숨김으로 표시됐다. 문서 좌표와 viewport 좌표를 구분하고 실제 Chromium에서 fixed 기준을 만드는 transform·filter·perspective·contain 등의 CSS를 확인했다. clip:rect는 실제 적용 위치 조건을 확인하며 단순 스크롤·부분 clip·이미지 font-size를 은닉으로 쓰지 않는다. pseudo는 DOM rectangle이 없으므로 margin/padding/border 보정이나 transform이 있는 경우 offset만으로 화면 밖을 확정하지 않는다. 실제 hit-test·CSS 기준 행렬·스크롤 전후·owner bounds/원문 불변을 함께 검사했다.
