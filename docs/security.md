# 접근과 데이터 처리 정책

## 로컬 세션 접근

점검자는 앱을 실행한 로컬 사용자다. 제품 계정·중앙 서버·계정 잠금 기능은 없다. 시작할 때 새 세션 토큰을 만들고 검증된 루프백 Host의 bootstrap 화면에만 제공한다. API·파일·DOM 근거·등록 PNG 요청은 같은 Bearer 토큰을 요구한다. 잘못된 토큰·다른 Origin·외부 Host·cross-site 요청은 거부한다. 재시작하면 이전 토큰은 폐기되며 새 토큰을 받아야 한다. 로컬 기기 자체를 장악한 다른 프로세스와 사용자를 격리하는 다중 사용자 서비스는 아니다.

| 주체 | 허용 조건과 동작 | 금지 |
|---|---|---|
| 로컬 화면 | 검증된 Host/Origin과 현재 세션 토큰으로 점검 시작·중단·등록 결과 조회 | 임의 파일 경로·명령·페이지 JS 실행 |
| 수집기 | 새 컨텍스트에서 공개 페이지·포함 iframe 읽기 | 로그인·폼 작성·비읽기 요청·외부 링크 순회 |
| AI 서비스 | 동의한 실행의 후보 텍스트·링크 CLEF 분류, OCR 선택 시 PNG 글자 추출 | 쿠키·전체 HTML·동의 없는 전송·미선택 이미지 전송 |
| Electron renderer | sandbox·context isolation, 로컬 HTTP UI | Node integration·외부 navigation·popup·임의 권한 |
| 배포 도구 | 고정 의존 자산·고지·허용된 소스 복사 | 개인 .env·결과 근거·Git 자료·shared node_modules 전체 복사 |

웹 화면은 수집 HTML을 텍스트로 표시하고 JSON만 다운로드한다. 이미지 미리보기는 실행에 등록된 input PNG만 인증·경로·해시 검증 후 image/png와 nosniff로 제공한다. 원본 SVG/HTML과 임의 URL을 화면 자원으로 실행하지 않는다. Electron은 검증한 blob JSON 다운로드만 허용하며 외부 실행 파일·원격 navigation을 열지 않는다. 릴리스에는 기존 디버그 브리지를 연결하지 않는다. Docker 내부 bind는 외부에 직접 공개하는 용도가 아니며 호스트 게시 포트는 루프백에 한정한다.

## 보호 대상과 보관

API 키·원문·근거·세션 토큰을 보호한다. 공개 페이지에도 개인정보가 있을 수 있으므로 원문 근거는 로컬 접근 권한과 운영자 보관 정책으로 관리한다. 자동 삭제·중앙 서버 보관은 제공하지 않는다. 정상 실행의 파일은 비공개 권한으로 작성하고 해시는 실제 바이트에 대응한다. 임의 경로 요청·symlink를 통한 저장 루트 밖 조회는 허용하지 않는다.

실행 ID·진입 URL·시작/종료·상태·카운트·탐지 원문/위치/기법·제외/미점검 URL·페이지/프레임/이미지/OCR/CLEF/저장 오류·조각/추출 상태·실제 요청 수·원본/PNG/결과 SHA256를 기록한다. 키·인증 헤더·쿠키·서비스 응답 원문을 오류 로그나 결과에 기록하지 않는다. 해시는 파일 무결성을 확인하며 법적 인증을 제공하지 않는다.

## 키와 외부 전송

OpenRouter 모델은 cloudflare/clef이며 OPENROUTER_API_KEY를 Node가 시작 시 읽는다. npm은 작업 폴더 .env, Docker는 지정 env-file, Windows는 실제 exe 옆 .env를 사용한다. OS 환경변수가 우선하며 변경 후 완전히 종료·재시작한다. 키 폐기·재발급은 사용자가 제공자에서 수행한다. 키 또는 CLEF 전송 동의가 없으면 실행 생성 전에 거부한다. 제품의 오프라인 광고 판정은 제공하지 않는다. 인증 실패·잔액/호출 제한·시간 초과는 검토와 미완료로 보존하며 키를 오류에 넣지 않는다.

CLEF는 필수며 화면에서 원문·정규화 텍스트·소유 링크 전송에 동의한다. OCR은 기본 꺼짐이고 켠 실행에서 같은 키로 google/gemini-3.8-flash에 정적 PNG를 전송한다. 전체 HTML·쿠키·방문 기록은 전송하지 않는다. 고정 endpoint·모델을 사용자 설정으로 우회하거나 실패 시 다른 모델로 자동 대체하지 않는다. PNG base64·원시 모델 응답을 로그에 남기지 않는다. 이미지 바이트·픽셀·시간·전체 요청 상한을 전송 전에 검사하며 재시도도 요청 예산에 포함한다. 입력 안의 지시문은 분석 자료로 처리한다. 실키·서명 키를 샘플·소스·배포물에 넣지 않는다. 화면 설정 응답에는 키 존재 여부만 포함한다.

## 기존 앱의 접근 경로

현재 Flutter AI는 보안 저장소에서 키를 읽고, Chrome AI는 암호화되지 않은 `chrome.storage.local`의 설정 객체에서 키를 읽는다. 어느 쪽도 공모전의 실행 시 `.env` 교체 규격을 충족했다고 간주하지 않는다.

## 기존 인증 페이지 처리의 한계

기존 Flutter 코드에는 Google·Microsoft·Apple 인증 호스트 및 GitHub·GitLab 로그인 경로에서 설정·요청 가로채기·일부 런타임 적용을 건너뛰는 판정이 있다. 그러나 WebView 초기 `initialUserScripts`는 URL 조건 없이 등록된다. 초기 스크립트에 같은 인증 배제 조건이 확인되지 않았으므로 '인증 페이지에는 모든 스크립트가 주입되지 않는다'고 보장하지 않는다. 실제 기기 재현은 수행하지 않았다.

새 점검 앱은 별도 브라우저 컨텍스트의 읽기 정책을 사용하며 이 초기 주입 경로를 사용하지 않는다. 기존 배제 함수를 가져왔다는 이유만으로 수집 범위 정책이 구현된 것으로 처리하지 않는다.

## 기존 디버그 자동화

Flutter 브리지는 디버그 빌드에서 루프백에만 열린다. 토큰이 설정되면 인증된 요청만 받는다. 토큰이 없으면 일반 동작은 가능하고 코드가 지정한 민감 동작은 거부한다. `page.getText`, `page.click`, `page.fill`은 민감 동작 목록에 없으므로 토큰 없이도 현재 페이지의 텍스트 읽기와 입력·클릭을 요청할 수 있는 코드 경로가 있다. 실제 기기에서 이 경로를 재현하지 않았다. 점검용 릴리스에서 브리지를 열거나, 이 구분을 검증된 포괄적 접근 제어라고 표현하지 않는다.

기존 Chrome 템플릿 서버는 기본적으로 루프백에 bind하지만 토큰 미설정 시 요청을 허용하고 CORS 기본값은 `*`다. 현재는 누락된 `scripts/lib.mjs` import 때문에 시작이 막히므로 실행된 서비스로 취급하지 않는다. 시작 문제를 고쳐 재사용한다면 인증과 허용 출처를 먼저 검증한다.

Android 서명 키와 기존 템플릿 서버 자격 증명은 재사용 코드에 남은 별도 보호 대상이다. 기존 릴리스 도구를 사용하는 경우에도 비밀 파일을 저장소에 넣지 않는다. 공모전용 Windows 도구에 Android 서명·템플릿 서버를 필수 설정으로 추가하지 않는다.
